# Чек на удачу

Покупатель регистрирует чек, модератор проверяет его в админке Django.

## Как запустить

```bash
cp .env.example .env
docker compose up --build
```

Сайт: http://127.0.0.1:8000/

Модератор — пользователь с флагом staff:

```bash
docker compose exec web python manage.py createsuperuser
```

Админка: http://127.0.0.1:8000/admin/

Регистрация покупателя: стандартная страница Django `/accounts/login/`. Отдельной саморегистрации нет: пользователя создаёт модератор в админке (`Пользователи`) либо через `createsuperuser`. Это сознательное упрощение: задание разрешает стандартный `django.contrib.auth` и не требует вёрстки входа.

Локальные тесты без Postgres:

```bash
pip install -r requirements.txt
set USE_SQLITE=1
set PROMO_START_DATE=2026-01-01
set PROMO_END_DATE=2026-12-31
python manage.py test receipts
```

## Что сделано

- Модель чека: ФН, ФД, ФП, дата и время покупки, сумма, статус, причина отказа, пользователь, дата регистрации.
- Серверная валидация: период акции из `.env`, сумма от 1000 ₽, уникальность ФН+ФД+ФП, новый чек всегда «на проверке».
- Личный кабинет: свои чеки от новых к старым, пагинация по 10, кнопка на форму.
- `GET /api/receipts/` отдаёт только чеки текущего пользователя. Параметры запроса владельца не меняют.
- Админка: смена статуса, причина обязательна при отказе.
- Форма на `fetch`, ошибки рядом с полями без перезагрузки.
- Мобильная вёрстка до 375px: одна колонка, таблица складывается в блоки, горизонтального скролла нет.

## Сверх задания

- Тесты валидации, дубля и изоляции API.

## Спорные места

**Повтор отклонённого чека.** Нельзя. Уникальность ФН+ФД+ФП действует всегда, независимо от статуса. Иначе один и тот же фискальный документ можно было бы гонять по кругу. Сообщение пользователю явное, без 500.

**Границы периода.** Даты в `.env` — календарные дни включительно в `TIME_ZONE` (по умолчанию `Europe/Moscow`). Покупка в 23:59 последнего дня входит в акцию, покупка в 00:00 следующего — нет. Часовой пояс браузера не используется: чек фиксирует локальное время кассы, и акция считается в одном поясе проекта. `datetime-local` сохраняется как время этой зоны.

**Форматы реквизитов.** ФН — 16 цифр, ФП — 10 цифр, ФД — 1–10 цифр. Это типичные длины фискальных реквизитов; задание длины не фиксирует.

**Вход.** Саморегистрации нет, чтобы не раздувать объём. Для проверки создайте пользователя в админке.
